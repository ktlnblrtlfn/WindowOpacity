# WindowOpacity

A Windows 10/11 x64 tray utility built with C#/.NET 8, WPF, Windows Forms' built-in notification icon, and documented Win32 APIs. No third-party NuGet packages, DLL injection, code injection, application binary changes, or administrator requirement.

## Run

Open `artifacts/WindowOpacity-win-x64/WindowOpacity.exe`. This self-contained single-file distribution includes the .NET runtime. It starts in the notification area. Activate a supported desktop window and click **◐**, immediately left of Minimize. Drag the slider to change opacity continuously. Right-click the caption control to reset; mouse-wheel increments are optional in Settings.

The tray menu provides Enable WindowOpacity, Reset All Windows, Settings, Run at Startup, About, and Exit. **Ctrl + Alt + Shift + O** restores the current foreground window. `WindowOpacity.exe --exit` requests a clean shutdown of the running instance. Only one instance runs per Windows session.

Use tray **Exit** for normal shutdown and restoration. Keep the published EXE in a permanent location before enabling Run at Startup; the per-user Run registry entry points to that location.

## Build

Open `WindowOpacity.sln` in Visual Studio 2022 with the .NET desktop development workload, or run from this directory with the .NET 8 SDK:

```powershell
dotnet build WindowOpacity.sln -c Release
dotnet run --project WindowOpacity/WindowOpacity.csproj -c Release
```

The framework-dependent executable is `WindowOpacity/bin/Release/net8.0-windows/WindowOpacity.exe`; keep its adjacent DLL/JSON files and install the .NET 8 Desktop Runtime.

To produce the standalone executable:

```powershell
dotnet publish WindowOpacity/WindowOpacity.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o artifacts/WindowOpacity-win-x64
```

Output: `artifacts/WindowOpacity-win-x64/WindowOpacity.exe`. Windows Desktop native runtime files are extracted by .NET on first launch. A PDB beside the EXE is optional for users and useful for debugging. The icon is original and generated by `scripts/GenerateIcon.py` using Python's standard library; it is already included, so Python is unnecessary for building.

## Architecture and safety

- `Native/`: centralized P/Invoke declarations, SDK constants, rooted WinEvent callback, and disposable event hooks.
- `Core/WindowTracker`: one foreground caption overlay and one popup. Events are installed on WPF's dispatcher message loop, coalesced, then dispatched to the UI thread. A two-second safety timer reconciles missed events. There is no high-frequency foreground polling.
- `Core/WindowFilter`: rejects shell surfaces, owned helpers, child/tool windows, invisible/cloaked/minimized windows, missing captions, excluded applications, inaccessible/higher-integrity processes, and existing layered renderers.
- `Core/TitleBarLocator`: first requests `WM_GETTITLEBARINFOEX` with a bounded `SendMessageTimeout`. Index 2 contains Minimize's physical screen rectangle. The overlay occupies an equally sized rectangle directly to its left. A separate conservative fallback uses the measured DWM caption cluster, window/frame bounds, and DPI metrics for known classic classes only. ChatGPT and Brave custom Chromium captions are supported by a read-only UI Automation adapter that verifies a measured Minimize/Maximize/Close triplet with English and Turkish labels. Other uncertain custom title bars are skipped.
- `Core/WindowOpacityService`: saves original extended styles before adding `WS_EX_LAYERED`, then applies `round(percentage * 255 / 100)` with `LWA_ALPHA`. At 100%, Reset, disable, normal exit, or handled dispatcher failure, it removes its layering bit. Unrelated style changes made meanwhile by the target are preserved.
- Window state belongs to the UI dispatcher. PID checks and a unique native window property identify the exact live window instance; HWND reuse within the same process cannot accidentally restore another window.
- `UI/`: nonactivating tool windows with no taskbar/Alt+Tab entries, rounded popup, English labels, vector/text caption icon, OS light/dark resources, and continuous slider changes. A temporary low-level mouse hook closes the popup on outside clicks without intercepting input or injecting code. Focus activation caused by accessibility clients is returned to the target.
- `Services/`: JSON settings, debounced executable-path opacity rules, per-user startup registration, tray icon, global hotkey, and throttled structured logs. Native APIs, hooks, timers, tray resources, and subscriptions are released at shutdown.

The manifest establishes Per-Monitor V2 awareness before creating UI. Caption placement and monitor bounds stay in physical Win32 pixels; popup dimensions convert WPF DIPs using the target's DPI. In Brave, a measured title-row Tab search dropdown is reserved: the transparency control sits just to its left with a DPI-scaled gap, rather than covering it. The popup is clamped to the target monitor's work area. Topmost placement is transient and only used while following the foreground target; unsupported foreground windows hide both controls.

## Settings and logs

Settings: `%LOCALAPPDATA%\WindowOpacity\settings.json`. Logs: `%LOCALAPPDATA%\WindowOpacity\Logs\yyyy-MM-dd.jsonl` (UTC timestamps). Repeated reasons are throttled for 30 seconds. Logs record operations, HWNDs, reasons, and native error codes without document text. Opacity rules store full executable paths, never HWNDs. Exclusions accept executable paths or filenames. Add Current Application uses the most recent eligible foreground target observed before Settings opened.

Minimum opacity defaults to 20%; Settings allows 20–95%. Existing layered windows are conservatively unsupported even when their alpha is readable, because external `SetLayeredWindowAttributes` may interfere with `UpdateLayeredWindow` rendering. They are never reset or otherwise changed by this utility.

## Verified behavior and limitations

See `docs/VALIDATION.md` for the actual validation record and remaining hardware/application coverage. Build success alone does not establish universal compatibility.

Normal shutdown and handled UI exceptions restore valid tracked windows whenever Windows permits. Forced termination, power loss, native process corruption, or an unresponsive/inaccessible target cannot guarantee restoration. This version has no external watchdog. If a process replaces its rendering strategy or strips external layering, the control becomes unsupported after the first failed change and is not repeatedly retried for that window's lifetime.

Some WPF renderers remove externally added `WS_EX_LAYERED`; the tested WPF fixture does so and is safely unsupported. Applications using custom/RTL captions, protected processes, elevated windows, full-screen presentation, or unusual compositor surfaces may also be skipped. Native caption APIs can report geometry that differs from an application's custom visual buttons; ChatGPT and Brave have a specific adapter, while other uncertain custom captions remain unsupported. The control occupies title-bar space and can obscure text or custom controls immediately beside Minimize. Mixed-DPI hardware, Windows 10, and the full requested application matrix require additional validation before claiming broad production compatibility.

## Tests and API verification

```powershell
dotnet run --project WindowOpacity.Tests -c Release -- classic wpf smoke notepad
./scripts/Verify-NativeConstants.ps1
```

Tests create and close their own blank windows. The optional `notepad` test skips if Notepad is already open to avoid touching existing documents. Run on an interactive Windows desktop without changing foreground windows during the test. UI Automation exercises the production executable, including the self-contained published EXE when selected by WINDOWOPACITY_TEST_EXE, rather than a mocked opacity API. Tests read actual window alpha/styles and compare physical caption rectangles. Test settings are isolated under `%TEMP%\WindowOpacity.Tests`.

The verification script checks 45 values against Microsoft's WinSDK headers. Reference documentation: [TITLEBARINFOEX](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-titlebarinfoex), [SetLayeredWindowAttributes](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setlayeredwindowattributes), [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook), and [Microsoft WinSDK headers](https://github.com/microsoft/win32metadata/tree/main/generation/WinSDK/RecompiledIdlHeaders).
